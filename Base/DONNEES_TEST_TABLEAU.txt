REQUÊTES SQL UTILES POUR DEBUG
================================================================================

-- Voir tous les personnels avec comptes:
SELECT id_personnel, username, actif, DATE(date_embauche) as date_emb 
FROM personnel 
WHERE username IS NOT NULL;

-- Voir un personnel spécifique:
SELECT * FROM personnel WHERE username = 'dupont.j';

-- Voir les demandes d'un personnel:
SELECT dc.id_demande_conge, dc.date_debut, dc.date_fin, sd.libelle as statut
FROM demande_conge dc
LEFT JOIN statut_demande sd ON dc.id_statut_demande = sd.id_statut_demande
WHERE dc.id_personnel = 1;

-- Vérifier le solde d'un personnel:
SELECT id_personnel, solde_annuel, solde_restant
FROM solde_conge
WHERE id_personnel = 1;

-- Voir tous les personnels actifs:
SELECT id_personnel, username, CONCAT(c.nom, ' ', c.prenom) as nom_complet, actif
FROM personnel p
LEFT JOIN candidat c ON p.id_candidat = c.id_candidat
WHERE p.username IS NOT NULL AND p.actif = 1;

================================================================================
TROUBLESHOOTING
================================================================================

Problème: "Utilisateur non trouvé" lors de la connexion
Solution: Vérifier que:
  1. Le username existe dans la table personnel
  2. Le champ 'actif' est à 1 (ou true/yes selon la BD)
  3. Pas d'espace avant/après le username
  
Problème: "Identifiants invalides"
Solution: Vérifier que:
  1. Le mot de passe est correct (les hashs sont sensibles à la casse)
  2. Refaire le hash BCrypt du mot de passe
  3. Vérifier que le hash est correctement inséré en BD

Problème: Connexion OK mais erreur "Personnel non trouvé" après
Solution: Vérifier que:
  1. Le champ 'personnel_id' de la table user_ pointe vers le bon personnel
  2. OU utiliser directement personnelRepository.findByUsername() (notre système)
